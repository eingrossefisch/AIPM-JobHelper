### 专家级真题解析 (QA 补充)

**1. 针对字节跳动：如何理解 Agent 与 Workflow 在行业落地中的关系？**
*   **答案要点**：
    *   **Workflow (工作流)**：是确定性的路径，适合逻辑严密、步骤固定的业务（如财务报销审批），PM 需要定义好节点和输入输出。
    *   **Agent (智能体)**：具有自主性、反思和工具调用能力，适合处理模糊需求或复杂决策（如私人旅行管家）。
    *   **落地策略**：在实际行业应用中，通常采用“Workflow-centric Agent”，即用工作流约束 Agent 的大框架，在框架内利用 LLM 的灵活性，平衡系统的稳定性与智能性。

**2. 针对暑期实习通用：如何平衡 AI 技术可行性与用户需求？**
*   **答案要点**：
    *   **需求降级**：当大模型当前准确率（如 85%）无法满足核心业务（如医疗诊断 99%）时，将 AI 角色从“决策者”降级为“助手/辅助检查”。
    *   **反馈闭环**：在 UI 层面设计反馈机制（赞/踩），利用用户数据喂给算法进行 **RLHF (强化学习)** 或策略调优。
    *   **边界设定**：在 PRD 中明确 AI 的能力边界，对于模型无法处理的 Top-N 以外的长尾需求，设计优雅的人工降级方案。

**3. 什么是 RAG？PM 在其中关注什么？**
*   **答案要点**：
    *   **定义**：**RAG (检索增强生成)** 即 LLM 生成回答前，先从私有知识库检索相关信息，再结合上下文生成。
    *   **PM 核心关注点**：
        1. **数据切片 (Chunking)**：知识库文档切多大？重叠度多少？直接影响检索精度。
        2. **检索质量**：Query 向量化后是否能召回最相关的内容（Top-K）。
        3. **成本体验权衡**：检索到的内容过多会导致 Token 消耗增加且可能引入噪音。

## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **模型评估** | 为什么在评价 AI 模型（如预测用户复购）时，不能只看“准确率 (Accuracy)”？如何通俗理解 AUC？ | **一句话解释**：准确率在样本不均衡时会“骗人”，而 AUC 衡量的是模型排定优劣的稳定性。<br>**核心逻辑**：<br>1. **样本偏差**：如果 100 个人里只有 1 个人买花，模型预测所有人都不买，准确率高达 99%，但这个模型完全没用（找不出目标用户）。<br>2. **指标权衡**：我们需要看**精准率 (Precision)**（推了的人里有多少真买，决定用户骚扰率）和**召回率 (Recall)**（想买的人里抓住了多少，决定业务增量）。<br>3. **AUC 的本质**：AUC 是 ROC 曲线下的面积。通俗讲，随机给模型一个“买家”和一个“非买家”，模型有多大的概率给“买家”打分更高。AUC 越接近 1，模型的排序能力和区分度就越好。 | 考察对业务场景中“数据分布不均”的敏感度，以及对模型业务价值的真实评价能力。 |
| **技术架构 (RAG)** | 针对企业知识库场景，你会选择 RAG（检索增强生成）还是微调（Fine-tuning）？ | **一句话解释**：RAG 是给模型看“参考书”（开卷考试），微调是让模型“记脑子里”（闭卷考试）。<br>**对比维度**：<br>1. **实时性**：RAG 优于微调。知识更新只需更新数据库索引，无需重新训练。对于法规、产品手册等高频更新场景，RAG 是首选。<br>2. **成本**：RAG 投入更低。微调需要算力、高质量标注数据且周期长；RAG 主要是向量数据库存储和检索开销。<br>3. **幻觉控制**：RAG 更好。RAG 能强制要求模型基于检索到的片段回答，并标注出处（溯源），大大降低胡编乱造的概率。<br>4. **结论**：事实性、时效性强的任务选 RAG；特定风格转换、垂直行业术语理解选微调。 | 考察对 LLM 落地成本、时效性、可靠性（幻觉）的 Trade-off（权衡）能力。 |
| **产品研发流程** | AI 产品的 PRD 撰写与传统功能性产品最大的区别在哪里？ | **一句话解释**：传统 PRD 定义“确定性逻辑”，AI PRD 定义“概率性边界”与“数据闭环”。<br>**核心差异**：<br>1. **从逻辑到数据**：传统研发关注 UI/UX 和业务逻辑；AI 研发的第一优先级是**数据定义**（样本从哪来、如何标注、特征是什么）。<br>2. **验收标准的变化**：传统 PRD 验收是“Pass/Fail”，AI 验收是“**统计学指标**”。PM 需要在 PRD 中明确：Bad Case 的容忍度、核心指标（如 F1-score）的基准线。<br>3. **反馈闭环 (Feedback Loop)**：PRD 必须包含上线后的数据回流设计，即如何收集用户反馈（点赞/点踩）来反哺模型持续优化，而不只是单次上线。 | 考察对 AI 产品研发底层范式（从流程驱动转向数据驱动）的理解深度。 |
