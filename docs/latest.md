## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **RAG vs 微调** | 面对业务需求，你应该如何选择 RAG（检索增强）还是 Fine-tuning（微调）？ | **一句话总结**：RAG 是给模型看“参考书”（外部知识库），微调是让模型“进脑子”（改变权重）。<br>**选择逻辑**：<br>1. **时效性**：数据实时更新（如新闻、库存）必选 RAG；模型需要学习特定行业话术或垂直领域风格，选微调。<br>2. **准确性**：RAG 允许“溯源”，点击查看原文可极大缓解幻觉问题；微调仍可能产生幻觉且难以排查。<br>3. **成本**：RAG 主要是向量数据库和 Embedding 成本，投入低起效快；微调需要高质量标注数据和昂贵的算力租赁。 | 考察对业务场景中“知识边界”的认知，以及对成本与收益的权衡能力。 |
| **Agent 架构** | 什么是 AI Agent？它与普通的 Prompt Chatbot 有什么核心区别？ | **一句话总结**：Chatbot 是“你问我答”的被动交互，Agent 是“给定目标、自主拆解、调用工具”的主动完成。<br>**核心能力**：<br>1. **规划 (Planning)**：Agent 能利用 CoT（思维链）将复杂任务拆解为子任务。<br>2. **工具使用 (Tool Use)**：通过 Function Calling 调用外部 API（如查天气、订机票、跑代码）。<br>3. **自我反思 (Reflection)**：Agent 能检查自己的执行结果，如果出错会修正路径重新尝试。<br>**PM 视角**：Agent 的核心难点在于“死循环”和“逻辑漂移”的治理。 | 考察对 LLM 从“对话工具”转向“生产力系统”技术路径的理解。 |
| **推理性能优化** | 大模型生成速度慢（Latency 高），PM 应该如何设计产品方案来优化用户体验？ | **一句话总结**：通过“技术掩护”和“流式反馈”来降低用户的体感等待时间。<br>**常用策略**：<br>1. **流式输出 (Streaming)**：采用 SSE 技术让字符一个个蹦出来，降低“首字响应时间 (TTFT)”，让用户先读起来。<br>2. **语义缓存 (Semantic Cache)**：对高频重复问题（如“怎么开票”）在向量空间做缓存，直接命中结果，不走大模型推理。<br>3. **异步任务设计**：长文本分析或视频生成任务，设计“进度条”或“完成后推送通知”，将同步等待转化为异步通知。<br>4. **模型路由**：简单任务调用轻量模型（如 GPT-4o-mini），复杂任务再分流给大模型，平衡速度与质量。 | 考察对 LLM 工程化痛点（慢、贵）的解决能力，以及对关键性能指标（TTFT、TPS）的理解。 |
