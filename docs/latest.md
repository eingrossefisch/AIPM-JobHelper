## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **工程落地/RAG** | 如何在保证 RAG 或 Agent 系统效果的前提下，有效优化 Token 成本？ | **通俗解释**：通过“能省则省、按需分配、预先缓存”的策略，减少昂贵大模型的使用频率和输入长度。<br>**1. 模型路由 (Router)**：根据任务难度分流。简单分类/意图识别用便宜的小模型（如 GPT-4o-mini），复杂逻辑推理才调用大模型（如 o1）。<br>**2. 语义缓存 (Semantic Cache)**：对高频重复问题建立缓存。如果用户新提问与历史问题语义高度相似，直接返回缓存结果，无需消耗推理 Token。<br>**3. 精细化检索 (Chunking)**：优化 RAG 的切片策略，通过更精准的召回（Rerank 排序）只给大模型喂最相关的 3-5 个片段，而不是全量塞入，减少 Prompt 长度。 | 考察对 Token 成本结构、模型分级策略（Model Tiering）以及系统工程化平衡能力的理解。 |
| **Agent 设计** | 在调用外部工具时，LLM “Tool Call” (直接调用函数) 和 “Code Interpreter” (写代码运行) 有什么区别？如何选型？ | **通俗解释**：Tool Call 是“按方抓药”（固定动作），Code Interpreter 是“现场做饭”（即兴创作）。<br>**1. 确定性与安全**：Tool Call 适用于业务逻辑固定的场景（如查库存、发邮件），可控性强、风险低；Code Interpreter 适用于数据分析、复杂计算，LLM 自行写代码解决问题，但存在代码运行报错或安全注入风险。<br>**2. 灵活性**：Code Interpreter 适合处理 PM 无法预穷举的逻辑，能处理极度个性化的用户需求。<br>**3. 决策建议**：B 端严谨业务首选 Tool Call，构建确定性工作流；数据科学、创意分析工具建议配置 Code Interpreter 插件。 | 考察对 LLM 动作执行（Action）机制的深度认知，以及对业务确定性 vs 灵活性权衡的判断。 |
| **复杂内容生成** | 针对 2000 字以上的长文本生成场景（如行业报告），如何解决 AI 容易“烂尾”或逻辑断裂的问题？ | **通俗解释**：不能让 AI 一次性“喷”出长文，而要采用“大纲驱动、分段填充、循环迭代”的流水线模式。<br>**1. 任务拆解 (Chain-of-Thought)**：第一步先让 AI 生成精细化大纲（三级标题）；第二步针对每个小节独立调用 Prompt 生成内容。<br>**2. 上下文透传**：在生成第 N 节时，将前 N-1 节的摘要或核心论点作为“记忆”输入，保证逻辑的一致性和连贯性。<br>**3. 幻觉控制**：在分段生成后，引入专门的验证 Agent（Critic）进行事实查证和风格润色。虽然增加了耗时和成本，但能极大提升长文可用率。 | 考察对 LLM 上下文窗口限制、幻觉积压效应的认知，以及设计复杂 Agent 工作流（Workflow）的能力。 |
