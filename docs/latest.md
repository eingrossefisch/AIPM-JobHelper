### 💡 专家深度解析与参考答案

#### 1. 如何防范大模型“幻觉”并建立评价标准？（针对网易/百度考点）
*   **答案要点**：
    *   **防范手段**：① **RAG (检索增强生成)**：给模型配“说明书”，强制其根据参考文档回答。② **Prompt Engineering**：在提示词中增加“如果不知道就回答不知道”或“请引用原文”的约束。③ **Self-Check**：利用另一路模型对生成结果进行一致性校验。
    *   **评价标准**：建立三层评测体系：**自动评测**（ROUGE/BLEU衡量文本重合度）、**模型评测**（LLM-as-a-judge，用强模型给弱模型打分）、**人工抽检**（针对业务核心场景进行 Bad Case 分析）。

#### 2. Agent 与“问答式”助手的核心区别？（针对百度考点）
*   **答案要点**：
    *   **产品逻辑**：问答式是“你问我答”，被动响应；**Agent** 是“目标导向”，具备任务拆解（Planning）和自主调用工具（Tool Use）的能力。
    *   **技术差异**：Agent 引入了**记忆系统**（Memory）和**反思机制**（Reflexion），能够处理多步复杂任务，而不仅是单次语义生成。

#### 3. 模型选型的决策框架（高精度 vs 低成本）？（针对百度场景题）
*   **答案要点**：
    *   **分层策略**：根据用户意图进行 **Router (路由器)** 路由。简单问题（如打招呼、简单事实查询）分配给低成本的小模型；复杂逻辑/长文本处理分配给大模型。
    *   **成本/体验平衡**：建立“质量-留存”函数。如果 20% 的错误会导致用户严重流失，则必须优先保质量；如果是容错率高的娱乐场景，则优先保速度。

| **Agent / 插件调用** | 让 LLM 进行 Tool Call（工具调用）和让它直接写 Python 代码跑逻辑，有什么区别？PM 该如何选？ | **结论**：Tool Call 侧重“意图识别”，写代码侧重“逻辑执行”。<br>**1. 确定性**：Tool Call 通过 Schema 约束输出，更适合调用已有业务接口；写代码灵活性极高，适合处理复杂的数学计算或数据清洗。<br>**2. 安全性**：写代码需要沙箱环境隔离（防止删库），成本和风险较高；Tool Call 相对可控。<br>**3. 成本**：Tool Call 消耗 Token 较少，写代码需要模型生成大量逻辑并多次调优，推理开销更大。 | 考察对 LLM 落地工程化路径的选择能力及风险意识。 |
| **RAG 性能优化** | 在优化 RAG 系统时，如何平衡响应延迟（Latency）和回答质量？ | **一句话解释**：通过“分层检索”和“异步处理”实现既快又准。<br>**1. 提速手段**：引入语义缓存（Semantic Cache），对高频问题直接命中；使用流式输出（Streaming）降低用户感知到的等待时间。<br>**2. 增效手段**：采用混合搜索（向量 + 关键词），解决专有名词检索不到的问题；引入 Rerank（重排序）模型，宁可检索时多拿数据，最后由高精度模型精选。<br>**3. 成本控制**：对存量文档进行清洗，减少冗余 Token；动态调整 Chunk Size（分块大小）平衡检索粒度。 | 考察对 RAG 核心痛点（慢、幻觉、成本）的工程调优思路。 |
| **AI 效果评测** | AI 项目上线后，如何定义算法指标与业务指标？当算法指标好但用户反馈差时怎么办？ | **一句话解释**：算法看“过程”，业务看“结果”，二者需通过 B-side 测试对齐。<br>**1. 算法指标**：准确率（Precision）、召回率（Recall）、幻觉率、Token 消耗比。<br>**2. 业务指标**：任务完成率（Task Success Rate）、用户留存、人工替代率（如智能客服）、单次任务成本（Cost per Task）。<br>**3. 冲突解决**：通常是评测集（Benchmark）与真实场景脱节。需构建“黄金测试集”，由 PM 标注真实业务 Case，强制算法模型向业务结果靠拢。 | 考察 PM 对 AI 产品特有的非确定性交付成果的量化管理能力。 |
