### 专家解析与真题答案参考

#### 1. 理想汽车：如何建立大模型验证体系（模型选型）？
*   **答案要点**：
    *   **多维评估集**：构建包含业务真实场景的 Benchmark（评测集），涵盖“基础能力（逻辑、指令遵循）”和“业务专有能力（如汽车领域知识）”。
    *   **评测方法**：采用 **LLM-as-a-judge**（如用 GPT-4 评测国产模型）、人工盲测（Side-by-side）以及关键业务指标（如：召回率、幻觉率、Token 成本、响应耗时延迟）。
    *   **灰度验证**：通过最小业务单元闭环测试，对比 A/B Test 数据（如用户采纳率或转化率）。

#### 2. 美团：如何利用 AI 为商家洞察经营价值？
*   **答案要点**：
    *   **结构化抽取**：利用 LLM 对碎片化评论进行 **NLP 情感分析**与属性抽取，将评价转化为“服务、菜品、环境、价格”四大维度的量化评分。
    *   **归因分析**：识别评论中的负面聚集点（如“上菜慢”），结合时间戳分析是否为高峰期运力不足。
    *   **行动建议**：AI 自动生成“经营周报”，直接给出建议（如：建议增加下午茶时段的团购券，因为评论提及下午光线好适合拍照）。

#### 3. 美团：AI 生成内容的 MVP 设计方案
*   **答案要点**：
    *   **数据准备**：筛选高分优质评价和商家官方图片作为 **Seed Data**（种子数据）。
    *   **Prompt 策略**：通过 **Few-shot**（少样本提示）约束生成风格，确保符合大众点评的社区氛围（如：多用 Emoji，语气口语化）。
    *   **闭环验证**：初期无需全自动，可采用“人机协同”模式，由 AI 生成初稿，运营简单审核后发布，重点观察用户的 **CTR (点击率)** 和 **停留时长**，而非追求完美覆盖。

## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **RAG** | 既然大模型窗口（Context Window）越来越大，为什么企业还要做 RAG？ | **结论**：长窗口是“临时扩容内存”，RAG 是“动态检索硬盘”。两者不是替代关系，而是成本与时效的博弈。<br>**1. 成本差异**：长窗口推理费用随 Token 线性增长，且首字延迟（TTFT）高；RAG 仅加载相关片段，大幅降低推理成本。<br>**2. 实时性**：RAG 只需更新数据库索引即可同步最新知识；模型微调或增加长上下文无法解决瞬时数据更新问题。<br>**3. 溯源性**：RAG 允许在回答中附带原文链接，消除“幻觉”并建立用户信任。 | 考察对 Token 成本、推理延迟（Latency）及数据更新策略的权衡能力。 |
| **Multi-Agent** | 什么时候该用 Multi-Agent（多智能体）架构，而不是单 Agent 完成任务？ | **结论**：单 Agent 像“一个人包揽全活”，多 Agent 则是“组建专业化团队”。<br>**1. 任务复杂度**：当任务链路过长（如：市场分析 -> 文案撰写 -> 图像生成）时，单 Agent 容易在长路径中迷失目标（Focus Loss）。<br>**2. 容错与调优**：多 Agent 可针对不同环节（如搜索、审核、执行）配置不同的 Prompt 或底层模型，实现局部调优且互不干扰。<br>**3. 稳定性**：多 Agent 允许设置明确的“检查点”，某个专家 Agent 失败后可针对性重试，而非整个流程重来。 | 考察对复杂业务流（Workflow）拆解及系统鲁棒性设计的理解。 |
| **效果评测** | 作为 AIPM，你如何量化评测一个生成式 AI 产品的好坏？（告别“体感评分”） | **结论**：建立“评测集 + 多维指标 + LLM-as-a-judge”的标准化体系。<br>**1. 黄金评测集（Benchmark）**：覆盖核心场景、边缘用例和攻击性测试的 Q&A 对。<br>**2. 核心指标**：针对 RAG 关注“检索召回率”和“回答忠实度”；针对对话关注“任务完成率”和“响应时间”。<br>**3. 自动评测**：利用能力更强的模型（如 GPT-4o）作为裁判，对候选模型的回答进行打分，并辅以人工抽检（Human-in-the-loop）确保一致性。 | 考察产品上线前的质量门禁（Gatekeeping）意识及数据驱动能力。 |
