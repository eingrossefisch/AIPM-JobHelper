| **LLM 基础/边界** | 请用通俗的话解释 LLM 的工作原理，并说清它的能力边界与产品风险。 | **通俗解释**：LLM 本质是在“根据上下文预测下一个最可能的词”，靠海量语料学到语言规律与知识的统计关联。<br>**怎么跑通的（PM要会讲清流程）**：用户输入（Prompt）→ 分词（tokenize）→ 模型基于上下文分布逐 token 生成 → 采样/解码策略（如 temperature、top-p）决定“稳/发散”→ 输出。<br>**核心能力**：语言理解与改写、信息归纳总结、结构化输出、一定的推理与规划（依赖提示与工具）、多语言迁移。<br>**能力边界（面试最常追问）**：1) **不保证事实正确**（会“编得很像真的”）；2) **对最新/私有知识无内置保证**（需外部知识注入如 RAG）；3) **长上下文会遗忘/注意力稀释**（长文档仍可能漏关键信息）；4) **确定性差**（同问不同答，需控制采样与模板）；5) **可解释性弱**（不能把“思考过程”当证据）。<br>**产品侧应对**：把 LLM 定位为“语言与决策建议引擎”而不是“真理引擎”；关键场景加 **引用来源/可追溯**、**高风险拒答**、**人审闭环**、**日志与评测**。 | 能否把“原理→能力→风险→产品护栏”串起来；是否理解幻觉/不确定性对交付与合规的影响。 |
| **RAG/知识库** | RAG 的完整链路是什么？为什么说 RAG 不是“把文档丢进模型”，落地时最容易翻车的点有哪些？ | **通俗解释**：RAG 就是“先去知识库检索证据，再让大模型按证据作答”，用外部知识约束生成、提升可追溯与可更新性。<br>**链路（端到端）**：数据接入/清洗→ 文档切分（chunk）与元数据（时间、来源、权限）→ 向量化与索引→ Query 改写/补全（让检索更准）→ 召回（向量/关键词混合）→ 重排（rerank）→ 拼接上下文（context packing）→ 生成（带引用/格式约束）→ 评测与反馈闭环。<br>**为何不等于“上传文档”**：上传是“把全文塞进上下文”，受 token/成本限制且难做更新与权限；RAG 是“按需取片段”，可控、可更新、可溯源。<br>**最容易翻车的点（PM可直接用于排障）**：1) **切分不合理**：语义断裂或片段太长导致噪声；2) **检索不准**：Query 太短/歧义、相似度阈值没调、缺少关键词检索兜底；3) **上下文塞爆**：召回太多导致模型抓不到重点；4) **数据保鲜**：知识过期但仍被召回；5) **权限与合规**：不同用户召回到不该看的文档；6) **只追求召回率不看可用率**：召回到了但不可读/不可引用。<br>**Trade-off（面试加分）**：RAG 的离线索引有成本，但能换来在线推理更便宜、更快；同时复杂度更高，需要数据工程+评测体系。 | 是否掌握 RAG 关键模块与“效果不佳”的系统性排查；能否从成本、延迟、可更新性、权限治理讲清取舍。 |
| **幻觉/可信与评测** | 什么是大模型幻觉？在企业场景你会用哪些组合拳降低幻觉，并怎么验证“真的变好”？ | **通俗解释**：幻觉就是模型在“不知道或证据不足”时，仍生成看似合理但不真实/不可验证的内容。<br>**常见成因（产品视角）**：1) 训练分布导致“编造式补全”；2) 提示词诱导（用户要求“必须给答案”）；3) 上下文证据不足或检索噪声；4) 长上下文关键信息被稀释；5) 生成策略过“发散”（temperature 高）。<br>**组合拳（按优先级）**：<br>1) **证据约束**：上 RAG/工具调用；要求“必须引用来源/只基于给定资料回答”，无证据就拒答。<br>2) **输出约束**：结构化模板（结论/依据/引用/不确定项）；关键字段做校验（数值、日期、实体）。<br>3) **推理与核验**：对高风险问题加二次校验（self-check/多模型交叉验证/规则校验），或让模型先列“需要的证据”再回答。<br>4) **策略与体验**：明确置信度与免责声明；提供“追问补充材料”而非硬答；关键链路引入 **Human-in-the-loop**。<br>5) **模型与解码**：降低 temperature、使用更强指令对齐模型；必要时对垂域做微调/偏好对齐。<br>**怎么证明变好（评测）**：离线用“带标准答案/标准依据”的测试集做：正确率、引用命中率、拒答准确率（该拒就拒）、幻觉率（无依据断言）、以及业务指标（工单减少/人工复核时长下降）；上线做 A/B（投诉率、采纳率、人工介入比例、时延与成本）。 | 是否理解“幻觉是系统问题”而非一句“模型不行”；能否提出可落地的治理手段与量化评测指标体系。 |
