## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **RAG (检索增强)** | 既然大模型长上下文 (Long Context) 能力越来越强，为什么还要做 RAG？ | **结论**：长窗口适合“精读”，RAG 适合“查书”。<br>**1. 成本差异**：长窗口随着 Token 增加，推理成本呈几何级上升且延迟（Latency）变高；RAG 仅检索相关片段，更省钱且响应快。<br>**2. 知识更新**：RAG 只需更新向量数据库即可获取最新信息，而无需重训或依赖模型训练截断期。<br>**3. 忠实度**：RAG 强制模型参考召回内容，并能通过“引用来源”消除幻觉，提供可追溯的证据。 | 考察对 **Token 成本、推理延迟与数据时效性** 的综合权衡能力。 |
| **Agent (智能体)** | 在设计 Agent 产品时，如何解决模型在复杂任务中“绕圈子”或死循环的问题？ | **原理**：死循环通常源于模型对“终止条件”判断失误或规划（Planning）逻辑冲突。<br>**PM解法**：<br>**1. 流程标准化**：将完全开放的任务拆解为 SOP 确定的工作流（Workflow），通过有向无环图（DAG）限制路径。<br>**2. 设置熔断**：在工程端强制设置“最大迭代步数”，防止算力无意义消耗。<br>**3. 引入反馈**：增加“判别器”节点或人工介入点（Human-in-the-loop），让模型在每一步后自我反思或接受校准。 | 考察对 **复杂任务流的容错设计** 及对 Agent 运行机制的深度理解。 |
| **幻觉与评测** | 大模型必然存在幻觉（Hallucination），作为 PM 如何构建上线前的技术评测集？ | **逻辑**：不能靠拍脑袋，必须建立业务敏感的“黄金数据集（Golden Dataset）”。<br>**1. 分类分级**：根据业务痛点，将评测分为事实性（精准度）、逻辑性（推导过程）和安全性（合规）。<br>**2. 引入 LLM-as-a-Judge**：利用更高能力的模型（如 GPT-4o）对候选模型输出进行多维度打分，解决人工评测效率低的问题。<br>**3. 关键指标**：关注“拒绝率”（模型在不知道时是否敢说不知道）和“幻觉触发率”。 | 考察对 **产品质量确定性** 的把控，以及如何量化 AI 产品的上线标准。 |
