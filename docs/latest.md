| **模型评估 (Eval)** | 如何评价一个 AI 产品的“好坏”？如果 AUC 很高但业务反馈差，可能是什么原因？ | **结论**：技术指标不等于用户价值，必须建立“端到端”的业务评测集。<br>**1. 指标失真**：AUC 是技术层面的排序能力，但若业务存在严重的样本不均衡（如 99% 都是负样本），模型即使躺平也能拿高分。<br>**2. 关注核心业务指标**：如**幻觉率**（事实错误比例）、**首字延迟 (TTFT)**、**任务完成率**（而非单纯的对话轮数）。<br>**3. 构建“黄金标准 (Golden Set)”**：人工标注 200-500 条真实用户 Case，每次迭代都要跑一次全量回归。 | 考察 PM 对模型性能指标与实际业务价值之间 Gap 的认知。 |
| **Agent / 流程** | 为什么现在的 Agent 在处理复杂业务流时经常“跑飞”？PM 如何设计容错机制？ | **结论**：LLM 的规划能力存在随机性，必须用“确定性流程”约束“不确定性模型”。<br>**1. 任务原子化**：将长链路拆解为多个 Step，每个 Step 只让模型做一个简单的选择或提取，避免长距离推理崩塌。<br>**2. 引入反思 (Reflection) 机制**：在输出结果前，增加一步 LLM 自查，判断结果是否符合预设的 JSON 格式或逻辑。<br>**3. 强人工干预 (Human-in-the-loop)**：在高风险决策节点强制停顿，由人工点击确认后再进行下一步。 | 考察对 Agentic Workflow（智能体工作流）的稳定性设计思路。 |
