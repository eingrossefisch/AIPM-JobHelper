## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **大模型架构** | RAG 和 Agent 的本质区别是什么？在设计产品逻辑时如何选型？ | **结论**：RAG 代表“增强记忆”，Agent 代表“增强行动”。<br>**原理**：RAG (检索增强生成) 是给模型外挂一本“参考书”，通过检索外部知识库解决模型训练数据滞后和幻觉问题。Agent (智能体) 则是给模型赋予“大脑、感官和手脚”，利用 LLM 的规划能力驱动工具（如调用 API、查天气、写代码）完成复杂任务。<br>**权衡**：如果你的产品目标是“查得准、回得快”，选 RAG；如果目标是“自动干活、闭环任务”，选 Agent。Agent 复杂度更高，需要考虑任务拆解的成功率和长链条推理的容错性。 | 考察对 LLM 主流应用范式的理解，以及在“信息检索”与“流程自动化”场景下的决策能力。 |
| **模型评估** | 在推荐或风控场景下，为什么看重 AUC/ROC 指标而非简单的准确率 (Accuracy)？ | **结论**：AUC 衡量的是模型的“排序能力”和在样本不平衡情况下的稳定性。<br>**通俗理解**：准确率在样本比例极端（如 1% 的用户买花，99% 不买）时会失效，模型只要全猜“不买”就有 99% 的准确率，但毫无业务价值。<br>**PM 视角**：AUC (ROC 曲线下的面积) 反映了模型将“正样本”（真买花的）排在“负样本”（不买花的）前面的概率。AUC 越接近 1，代表模型给高潜用户打分越高，这直接决定了 push 营销的 ROI 或信贷风控的拦截率。 | 考察对机器学习基本评价指标的掌握，以及能否将技术指标转化为业务价值（如 ROI/获客成本）。 |
| **技术路径方案** | 面对企业私有化部署需求，解决“大模型不懂业务知识”该选 RAG 还是 Fine-tuning (微调)？ | **结论**：动态知识看 RAG，静态能力看微调。<br>**权衡点**：<br>1. **知识时效性**：RAG 可实时更新（如最新财报），微调需要重训，时效差。<br>2. **成本与算力**：RAG 是“外挂”，成本低；微调需高质量标注数据和昂贵的 GPU 算力。<br>3. **幻觉控制**：RAG 提供“信源溯源”，能显著降低幻觉；微调只是改变模型概率分布，仍可能一本正经胡说八道。<br>4. **适用场景**：微调适用于让模型学习特定格式（如医疗病历写作风格）或增强垂直领域理解。 | 考察对落地成本、数据工程难度以及 LLM 局限性（幻觉）的深度认知。 |
