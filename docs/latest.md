### 核心真题 QA 深度解析

#### 1. 百度：如何构建模型选择的决策框架（巨型模型 vs 小模型）？
*   **面试考点**：**成本效率权衡 (Cost-Efficiency Trade-off)** 与 **意图分流 (Query Routing)**。
*   **参考答案**：
    *   **建立分流器 (Router)**：通过轻量级模型对用户意图进行分类。简单、长尾或格式化任务（如打招呼、改写）由**小模型**处理；复杂逻辑、多步推理（如代码、专业咨询）由**巨型模型**处理。
    *   **定义阈值**：基于业务场景设定 **P99 耗时**和 **单位 Token 成本**。若为高频 C 端工具（如输入法 AI），速度优先；若为专业 B 端工具（如法律顾问），质量优先。
    *   **降级策略**：若大模型响应超时，自动切换至小模型并增加“结果仅供参考”的提示。

#### 2. 字节跳动：Agent 任务失败时的兜底方案设计？
*   **面试考点**：**容错设计 (Fault Tolerance)** 与 **用户体验管理 (Expectation Management)**。
*   **参考答案**：
    *   **重试与切换**：若模型输出解析失败（JSON 报错），进行 1-2 次静默重试或更换推理温度 (Temperature) 重新生成。
    *   **确认机制**：在执行关键动作（如支付、删除）前，强制增加人工确认环节，将 AI 的“决策”权转交给用户的“审查”权。
    *   **透明化引导**：若工具调用返回空结果，不直接报错，而是引导用户补充信息。例如：“我尝试查询了 10:00 的高铁但已售罄，是否需要我为您推荐附近时段或二等座？”

#### 3. 通用考点：如何理解 RAG 中检索与生成的平衡？
*   **面试考点**：**幻觉抑制 (Hallucination Mitigation)** 与 **置信度计算**。
*   **参考答案**：
    *   **检索端 (Retrieval)**：设定相似度阈值。若检索到的片段分值低于 0.6，则倾向于告知用户“未找到相关知识”，防止模型强行通过自身权重“脑补”。
    *   **生成端 (Generation)**：在 **Prompt** 中明确限制，要求模型必须引用文末参考链接。若外部知识与模型常识冲突，通过指令设定优先级（知识库 > 模型自生成）。

## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **RAG vs. SFT** | 如何根据业务需求判断该用 RAG（检索增强生成）还是 SFT（微调）？ | **一句话解释**：RAG 是给模型提供“参考书”（开卷考试），SFT 是让模型“背课本”（闭卷考试）。<br>**PM决策逻辑**：<br>1. **实时性**：如果数据秒级更新（如新闻、内部文档），首选 **RAG**，因为 SFT 重新训练成本极高且有滞后。<br>2. **成本**：**RAG** 门槛低、见效快；**SFT** 需要高质量标注数据和昂贵算力。<br>3. **准确性**：需要引用溯源、消除幻觉的场景用 **RAG**；需要学习特定格式、语气或极度专业垂直领域的逻辑用 **SFT**。 | 考察对技术选型成本、数据时效性及落地可行性的权衡能力。 |
| **Agent 工作流** | 在设计 AI Agent 时，如何解决复杂任务中模型“思路断层”或“执行失败”的问题？ | **一句话解释**：不要指望模型一步到位，要通过“规划（Planning）+工具调用（Tool Use）+反思（Reflection）”构建工作流。<br>**PM设计思路**：<br>1. **拆解**：利用 CoT（思维链）将大目标拆解为子任务。如果一步错了，Agent 能在子节点纠错。<br>2. **闭环**：引入“反思机制”，让模型生成结果后自我检查是否符合用户指令。<br>3. **人工介入（HITL）**：在关键决策节点（如涉及资金、删库）强制增加人工确认，防止模型在循环中失控。 | 考察对 Agent 架构逻辑（ReAct 框架）及复杂业务风险控制的设计能力。 |
| **模型评测** | 业务上线前，如何建立一套科学的 LLM 评测体系（Eval）？ | **一句话解释**：弃用“感觉模型变聪明了”这种主观评价，建立由“基础基准 + 业务黄金集 + 模型竞技场”组成的量化体系。<br>**实施策略**：<br>1. **构建 Golden Dataset**：针对业务场景筛选 200-500 条代表性 Case，设定标准答案。<br>2. **多维打分**：引入 **LLM-as-a-judge**（用 GPT-4 给其他模型打分）提高效率，辅以人工抽检。<br>3. **关注负面指标**：重点评测安全性（不回答违规内容）、拒绝率（该答的是否拒答）和 Token 消耗成本。 | 考察对产品上线质量标准、量化管理及 AI 落地闭环的专业度。 |
