### 💡 专家深度解析与参考答案

#### 1. 网易互娱：如何防范大模型“幻觉”及制定上线标准？
*   **如何防范幻觉？**
    *   **RAG (检索增强生成)**：通过外部知识库（如文档、数据库）为模型提供事实依据，将生成过程限制在已知资料范围内。
    *   **Prompt Engineering**：在提示词中加入约束（如“仅根据已知内容回答”、“不知道请说不知道”）或使用 **Few-shot** 示例引导。
    *   **Self-Correction**：引入多步验证，让模型对生成的初稿进行二次检查，或使用另一个模型进行反向验证。
*   **上线标准指标：**
    *   **准确率 (Accuracy)**：对于分类任务需达到 90%+；对于总结任务，通常通过 **Human Eval**（人工抽检满意度）需达到 85% 以上。
    *   **安全性 (Safety)**：拦截违规内容的成功率需接近 100%。
    *   **延迟 (Latency)**：首字响应时间 (P99) 需控制在用户可感知的阈值内（如 < 2s）。

#### 2. 腾讯：本科 vs 研究生就业的选择逻辑
*   **考察维度**：面试官主要考察候选人对 **AI 行业爆发期** 的敏锐度以及自我驱动力。
*   **参考答案**：
    *   **技术迭代速度**：AI 领域目前处于“日更”状态，工业界的落地经验（如 **Agent** 编排、**RAG** 调优）往往领先于学术界的理论研究，早期进入实战环境能更快建立行业认知。
    *   **应用层机会**：对于 AIPM 而言，理解业务场景与模型能力的边界比推导算法公式更重要，本科阶段积累的互联网产品直觉是转型的核心优势。
    *   **学习路径**：通过工作中的实际项目驱动，利用大模型辅助进行“非线性”学习，效率可能高于传统的学术深造。

## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **知识检索 (RAG)** | 为什么企业级知识库优先选 RAG 而不是微调 (Fine-tuning)？ | **原理逻辑**：RAG 是给模型提供“外挂参考书”，模型根据问题去书里找答案再总结；微调是让模型“背课本”，把知识内化到参数里。<br>**Trade-off**：1. **时效性**：RAG 增删文档秒级生效，微调需重新训练模型；2. **成本**：RAG 仅需向量数据库维护费，微调涉及高昂算力和数据清洗成本；3. **可信度**：RAG 可提供原文出处（溯源），有效抑制幻觉。<br>**适用场景**：动态更新的文档、需要高准确率的业务知识库必选 RAG。 | 考察对知识更新成本、数据安全性及幻觉治理的理解。 |
| **智能体 (Agent)** | 如何评估一个 AI Agent 系统的稳定性和实用性？ | **核心指标**：不能只看单次回答，要看“任务完成率 (Success Rate)”。<br>**维度拆解**：1. **规划能力 (Planning)**：面对复杂指令，Agent 能否正确拆解步骤而不陷入死循环；2. **工具调用 (Tool Use)**：能否在正确时机调用正确的外部 API 且参数传递准确；3. **反思能力 (Self-reflection)**：当步骤出错时，模型能否根据反馈自主纠偏。<br>**PM 视角**：需要设计“人工干预节点 (Human-in-the-loop)”，在关键决策环节由人确认，降低模型失控风险。 | 考察对复杂任务流设计、容错机制及非确定性产品评测的经验。 |
| **模型评测 (Eval)** | LLM 产品上线前，如何构建业务专属的评测集 (Benchmark)？ | **核心逻辑**：拒绝“体感测评”，必须量化。构建包含“Input-Golden Answer”的黄金测试集。<br>**分层设计**：1. **基础层**：覆盖业务高频 Query（如 80% 的常见问题）；2. **边界层**：构造 Corner Case（如误导性提问、非法请求）；3. **对比层**：新旧版本模型或 Prompt 的 A/B Test。<br>**评测方法**：采用 **LLM-as-a-Judge**（如用 GPT-4 给自研模型打分）提高效率，辅以人工盲测 (Blind Test) 确保主观体验一致。 | 考察如何将模糊的 AI 效果转化为可度量的产品指标。 |
