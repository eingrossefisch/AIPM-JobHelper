### 💡 专家核心考点解析 & 答案参考

#### 1. 关于字节跳动的 MCP 协议问题
*   **问题核心**：考察候选人对 AI 前沿工程标准的关注度。
*   **参考答案**：**MCP** 是由 Anthropic 发起的开放标准，旨在解决 LLM 与外部数据源/工具（如 Google Drive, Slack）连接时的“接口碎片化”问题。PM 应关注其带来的“即插即用”生态能力，降低 Agent 集成不同数据源的开发成本，使 AI 能够更低成本地获取实时上下文。

#### 2. 关于美团的 ETA 准确率量化问题
*   **问题核心**：考察 AI 产品经理对算法模型转化成业务收益（ROI）的评估能力。
*   **参考答案**：
    *   **用户侧**：提升预期准确性，降低因“配送超时”导致的退款率及客服人工申诉成本。
    *   **骑手侧**：优化排班与路线调度，减少骑手原地等待时间，提升人效。
    *   **平台侧**：提升整体履约效率（On-time rate），增强用户对“准时”的心智信任，提高下单复购率。

#### 3. 关于 AI “真/伪需求” 的判断原则
*   **问题核心**：考察 PM 的核心产品功底，避免盲目追逐大模型热度。
*   **参考答案**：
    *   **真需求**：具备“高频、低容错度要求或高增量价值”特征。例如 AI 翻译（跨语言沟通是刚需且传统方案效率低）。
    *   **伪需求**：流程更繁琐（如用对话式 AI 去做“一键静音”这类开关操作）、成本远超收益（昂贵的 Token 只为解决一个简单的正则匹配逻辑）、或用户对幻觉（Hallucination）零容忍的严谨场景。

## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **RAG 架构** | 既然大模型上下文窗口（Context Window）越来越大，为什么还要用 RAG 技术？ | **结论**：长窗口虽能容纳更多信息，但 RAG 在成本、时效性和可解释性上仍有绝对优势。<br>**1. 成本控制**：长窗口是“按输入全量计费”，每次提问都要带上所有背景资料，极其昂贵；RAG 只检索最相关的片段，Token 成本极低。<br>**2. 知识更新**：RAG 只需更新数据库索引，秒级生效；若靠长窗口或微调，不仅更新慢，且无法处理海量私域数据。<br>**3. 消除幻觉**：RAG 提供“信源追溯”，能明确标注回答来自哪份文档，增加用户信任感。 | 考察对产品架构选型、Token 成本（Cost-efficiency）和业务实效性需求的权衡能力。 |
| **性能与交互** | LLM 推理响应慢、首字延迟（TTFT）高，作为 PM 你如何从技术和产品层面优化？ | **结论**：不能死等模型跑完，要通过“流式输出”和“异步交互”解决用户焦虑。<br>**1. 流式展示 (Streaming)**：采用 SSE 协议，实现“蹦字”效果，将用户的感知延迟从数十秒降至毫秒级。<br>**2. 提示词缓存 (Prompt Caching)**：对固定的背景知识或 System Prompt 进行缓存，减少重复计算，不仅提速还能省钱。<br>**3. 任务拆解与进度反馈**：如果是复杂任务（如 Agent 找资料），在前端展示“正在搜索...”、“正在归纳...”等节点状态，通过交互设计掩盖技术性能瓶颈。 | 考察对 LLM 关键性能指标的理解，以及通过产品手段解决技术局限性的工程化思维。 |
| **幻觉与评测** | 在业务上线前，你如何科学地评测模型是否存在“幻觉”，并降低其业务风险？ | **结论**：幻觉不可消除只能抑制，需构建“自动评测+人工抽检”的闭环体系。<br>**1. 建立 Goldset (金标集)**：针对核心业务场景构建包含标准答案的 Prompt 测试库，上线前进行回归测试。<br>**2. 引入反思机制 (Self-Reflection)**：在 Agent 流程中加入“自我检查”环节，让模型输出前先对比原文，判断是否捏造事实。<br>**3. 护栏设计 (Guardrails)**：在输出端加一层小模型或正则过滤，识别并拦截涉及政治、暴力或严重偏离事实的回答，确保安全合规。 | 考察对模型不确定性（Probabilistic）的认知，以及对产品质量保障（QA）体系的构建能力。 |
