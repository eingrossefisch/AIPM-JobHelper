### 专家级真题解析与答案参考

#### 1. 百度：如何平衡 RAG 检索知识与模型生成能力？
*   **面试官视角**：考察对 **RAG** 局限性的认知（如：检索噪声、模型对检索内容的过度依赖或忽略）。
*   **参考答案**：
    *   **置信度分流**：为检索内容设定相关性阈值，低相关时依赖模型原生能力，高相关时强制参考。
    *   **Prompt 约束**：在提示词中明确指令，要求模型对比检索内容与自身知识库，若发生事实冲突，优先以检索到的实时/私有数据为准。
    *   **反思机制**：引入 Self-RAG 概念，让模型先判断是否需要检索，再判断检索内容是否解决问题，最后对生成的答案进行事实性校验。

#### 2. 百度：模型选择的决策框架（大模型 vs 小模型）？
*   **面试官视角**：考察产品经理对 **成本、体验、商业化** 的综合权衡能力。
*   **参考答案**：
    *   **任务分级**：对任务进行分类。简单任务（如翻译、润色）走小模型；复杂推理（如逻辑分析、多步规划）走大模型。
    *   **瀑布流架构**：先由小模型判断意图，无法处理时再路由给大模型。
    *   **阈值决策**：根据当前系统的并发压力和用户等级进行动态调度（如 VIP 用户分配高资源模型，高峰期自动降级）。

#### 3. 理想汽车：如何定义大模型评测的核心指标？
*   **面试官视角**：考察 AIPM 的数据敏感度及对 **评价对齐（Alignment）** 的理解。
*   **参考答案**：
    *   **客观指标**：针对事实性任务，关注 **准确率**（基于 Ground Truth）和 **Hallucination Rate**（幻觉率）。
    *   **主观指标**：引入 **Human-in-the-loop**，通过 Side-by-Side (SBS) 盲测，计算 **胜率（Win Rate）** 和 **Elo 分数**。
    *   **性能指标**：**TTFT**（首字响应时间）和 **TPS**（每秒生成 Token 数），这直接决定了车载语音等场景的用户体验。

#### 4. 理想汽车：有监督与无监督学习的区别及场景？
*   **面试官视角**：考察 AIPM 的基本算法功底，判断是否能与算法工程师高效沟通。
*   **参考答案**：
    *   **区别**：有监督学习需要“标签”（Labels），模型学习特征到标签的映射；无监督学习处理无标签数据，旨在发现数据内部的结构或分布。
    *   **场景应用**：
        *   **有监督**：车载摄像头的障碍物识别（需人工标注车辆、行人、红绿灯）。
        *   **无监督**：用户画像聚类（基于座舱交互数据，将用户自动分类为“商务型”或“家庭型”而不预设标签）。

| **RAG 优化** | 为什么 RAG 系统在连接了私有知识库后，仍然会产生“幻觉”或回答错误？ | **核心逻辑**：主要由“检索不准”或“处理不当”引起，而非模型本身能力不足。<br>**解决思路**：<br>1. **清洗侧**：对 PDF/文档进行精细化解析，去除表格、图片干扰，提升“数据喂入”的质量。<br>2. **策略侧**：优化“切片（Chunking）”大小，避免语义断裂；引入 **Re-ranking（重排序）** 机制，确保最相关的文档排在最前面。<br>3. **提示词**：在 Prompt 中明确约束“若知识库无相关内容，请回答不知道”，防止模型强行发挥。 | 考察对 RAG 全链路（数据解析-检索-生成）的深度认知及调优经验。 |
| **性能与交互** | LLM 生成速度慢（高延迟）是行业通病，你如何通过产品设计缓解用户的焦虑？ | **技术手段**：<br>1. **流式输出（Streaming）**：像打字机一样逐字显示，让用户感知到系统正在响应，而非死机。<br>2. **模型分流（Model Routing）**：简单指令用小模型（如 GPT-4o-mini / DeepSeek-V3），复杂逻辑才调用大模型。<br>**交互手段**：<br>1. **预加载与占位**：在等待时提供“预处理进度条”或相关的背景知识提示。<br>2. **结果缓存**：针对高频重复问题，通过语义索引直接命中缓存结果，实现毫秒级响应。 | 考察在技术瓶颈下，通过产品策略优化用户体验（UX）的变通能力。 |
| **模型选型/成本** | 在商业落地时，如何决定使用闭源模型（如 GPT-4）还是私有化部署开源模型（如 DeepSeek/Llama）？ | **决策维度**：<br>1. **数据安全性**：涉及政府、金融等核心敏感数据，优先选择私有化部署开源模型。<br>2. **成本 ROI**：高频低复杂度任务（如分类、摘要）用开源模型+微调，Token 成本可降低 80% 以上；追求极致智商的任务（如代码编写、复杂推理）用闭源旗舰。<br>3. **稳定性与迭代**：闭源模型 API 简单稳定，适合快速打梦验证；开源模型自主可控，适合长期大规模业务沉淀。 | 考察作为 PM 对业务场景、数据合规及技术 ROI（投入产出比）的权衡能力。 |
