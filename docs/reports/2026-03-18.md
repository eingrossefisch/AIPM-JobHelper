## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **多智能体 (Multi-Agent)** | 既然单个模型（如 GPT-4o）已经很强，为什么复杂业务还需要多智能体（Multi-Agent）架构？ | **结论**：单个模型存在“能力边界”和“注意力稀释”，多智能体通过分工（Role Play）解决复杂长链路问题。<br>**逻辑**：类比公司架构。单 Agent 像个全能但易疲劳的个体，多 Agent 则是“策划+执行+审核”的流水线。例如：Agent A 负责检索资料，Agent B 负责写作，Agent C 负责校对扣分。<br>**Trade-off**：优点是准确率显著提升、任务可拆解可回溯；缺点是 Token 消耗成倍增长、推理延迟（Latency）大幅增加，且 Agent 间的通信可能产生“误差传递”。 | 考察对复杂任务流（Workflow）的拆解能力及对成本/性能平衡的理解。 |
| **知识获取 (RAG vs Fine-tuning)** | 面对企业内部海量的动态文档，PM 应该选择 RAG（检索增强生成）还是微调（Fine-tuning）方案？ | **结论**：首选 RAG。RAG 相当于“开卷考试”，微调相当于“闭卷背诵”。<br>**对比点**：<br>1. **实时性**：RAG 挂载数据库，更新文件即可生效；微调需重新训练，成本高、周期长。<br>2. **准确性**：RAG 能给出证据溯源（Citation），有效缓解幻觉；微调后的模型容易“一本正经胡说八道”。<br>3. **适用场景**：微调更适合让模型学习特定的语态（如周报风）、特定格式或极深度的行业黑话。 | 考察对 AI 基建选型的认知，以及对“幻觉”治理手段的掌握。 |
| **模型评测 (Evaluation)** | 在模型上线前，PM 如何构建一套科学的评测体系，而不是只靠“拍脑袋”体感测试？ | **结论**：必须建立“黄金数据集（Golden Set）”+“自动化评估（Model-as-a-Judge）”的闭环。<br>**步骤**：<br>1. **构建 Testset**：覆盖业务 80% 核心场景，包含边界 Case（Bad Cases）。<br>2. **量化指标**：除了通用的准确率，还需关注“幻觉率”、“安全性”和“响应时间”。<br>3. **评估手段**：人工抽检（昂贵但精准）vs 模型互测（用最强的模型如 GPT-4o 给待测模型打分，高效且可规模化）。 | 考察对 AI 产品质量控制（QA）的专业性，以及数据驱动迭代的思维。 |
