## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **多智能体 (Multi-Agent)** | 相比单智能体（Single Agent），多智能体架构的核心优势与落地挑战是什么？ | **核心优势**：通过“分工”突破模型上下文限制和能力边界。例如：Planner智能体负责规划，Executor负责执行，Reviewer负责校验。这能显著提升任务的鲁棒性（交叉校验降幻觉）和并行效率（任务拆解后多线处理）。<br>**落地挑战**：1. **成本控制**：Agent间频繁通信会导致 Token 消耗指数级上升；2. **协同风险**：智能体之间可能产生“理解偏差”导致任务陷入死循环或输出不一致；3. **响应延迟**：环节越多，端到端延迟（Latency）越长，用户体验下降。 | 考察对复杂大模型系统架构的 Trade-off（权衡）能力，以及对成本和效率的敏感度。 |
| **模型评测 (Evaluation)** | 如何建立一套有效的模型评测指标，判断产品是“变好了”还是“变差了”？ | **结论**：不能只看算法侧的 Loss 或 Perplexity，PM 需构建“业务评测集”。<br>**核心指标**：1. **准确率/成功率 (Success Rate)**：针对具体业务场景（如报销审批）的端到端任务完成率；2. **幻觉率 (Hallucination Rate)**：通过构建 Ground Truth（金标准数据）对比模型输出，评估信息真实性；3. **LLM-as-a-judge**：引入更强的模型（如 GPT-4o）对业务输出进行分类打分。<br>**PM行动**：当模型更新版本时，必须用“固定评测集”跑回归测试，防止解决 A 问题的同时引入 B 问题。 | 考察对 AI 产品质量确定性的把控方法，以及如何将模糊的技术指标转化为业务价值。 |
| **故障诊断 (Troubleshooting)** | 当 AI 输出不符合预期时，你如何判断是 Prompt 问题、工程（RAG）问题还是模型边界问题？ | **排查逻辑**：1. **Prompt 层面**：如果模型完全不按指令执行或格式混乱，优先优化 Prompt（如增加 Few-shot 或 CoT）；2. **工程/RAG 层面**：如果模型回答“我不知道”或信息过时，说明检索召回的上下文（Context）不全或分片不对，需优化 RAG 流程；3. **模型边界**：如果已经提供了完整上下文且 Prompt 清晰，模型依然无法处理复杂的逻辑推理，则说明当前模型参数量或逻辑能力已达上限，需切换更高级别的模型或进行微调（Fine-tuning）。 | 考察对 LLM 全链路技术栈的理解深度，以及快速定位线上问题的实战能力。 |
