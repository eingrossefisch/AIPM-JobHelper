| **LLM 基础认知** | 请用通俗语言解释 LLM 的工作原理，并说明它的核心能力边界是什么？（如何跟业务方讲清“能做/不能做”） | **一句话**：LLM 本质是“根据上下文预测下一个词”的超级语言压缩器/模式匹配器，强在生成与归纳表达，弱在“保证事实正确”和“稳定可控”。<br><br>**它怎么跑通的（PM视角）**：<br>1) **预训练**：在海量文本上学会语言规律与知识的统计关联（像把互联网语料“压缩”进参数）。<br>2) **指令对齐**：通过指令微调/人类反馈（如 RLHF）让它更愿意“按要求回答”、更像助手。<br>3) **推理阶段**：输入 prompt → 模型按概率一步步续写 → 得到回答；输出受提示词、上下文长度、采样策略影响。<br><br>**核心能力**：<br>- **文本理解与生成**：总结、改写、翻译、生成结构化草稿（PRD/邮件/脚本）。<br>- **弱监督推理**：能做“看起来合理”的推断与链路解释（但不保证对）。<br>- **工具调用/工作流编排**（配合 Agent/函数调用）：把“语言”变成“操作指令”。<br><br>**能力边界/风险（面试要点）**：<br>- **事实性不保证（幻觉）**：尤其是企业私有知识、最新信息、长尾细节。<br>- **可控性有限**：同一问题多次回答可能不一致；对 prompt 很敏感。<br>- **长上下文≠长记忆**：窗口内信息可能被忽略；窗口外完全不记得。<br>- **合规与安全**：敏感信息、版权、提示注入等会导致业务事故。<br><br>**产品落地的“兜底策略”**：关键场景要配 **RAG/引用证据/审核/拒答**；把 LLM 定位为“提升效率的副驾驶”，而不是“最终裁决者”。 | 是否能把“LLM不是知识库/不是规则引擎”讲清楚；能否从产品风控角度给出边界与兜底；是否理解对齐、上下文窗口、稳定性与一致性问题。 |
| **RAG（检索增强生成）** | 面试官问：为什么企业知识问答优先用 RAG？一个可落地的 RAG 系统你会怎么设计与优化？ | **一句话**：RAG=“先从企业知识库检索证据，再让模型基于证据回答”，用外部知识补齐模型记不住/不可信的问题，并把回答变得可追溯。<br><br>**为什么用 RAG（对比微调/长上下文）**：<br>- **更新快**：知识变了只需更新库/索引，不必重新训练。<br>- **可追溯**：能返回引用片段/来源链接，便于审计与客服兜底。<br>- **成本可控**：比把大量材料塞进长上下文更省 token；比频繁微调更轻。<br><br>**典型链路（PM能画出流程图）**：<br>1) 数据接入（文档/FAQ/工单/网页）→ 2) 清洗切分（chunk）→ 3) 向量化&索引（向量库/倒排）→ 4) 查询改写（补全意图/抽关键词）→ 5) 召回（向量相似度+关键词过滤）→ 6) 重排（rerank）→ 7) 生成（带引用的回答）→ 8) 反馈闭环（命中率、拒答、纠错）。<br><br>**面试高频痛点&优化抓手**：<br>- **检索不准**（召回偏/噪声大）：做 **Query 改写、关键词过滤、相似度阈值、按业务字段/时间/章节过滤、混合检索（BM25+向量）**。<br>- **切分不合理**（证据不完整/上下文断裂）：按标题层级切分、滑窗、加入元数据（产品线/版本/发布日期）。<br>- **召回多但不相关**：引入 **rerank**，以及“证据不足则拒答”。<br>- **知识过期**：建立 **数据保鲜机制**（发布-下线流程、版本号、更新时间、责任人）。<br><br>**成本与性能 trade-off**：<br>- chunk 越小召回更准但索引更大；chunk 越大 token 更贵且易引入噪声。<br>- rerank 提升质量但增加延迟；可对高价值问题才启用或做分级。<br><br>**交付物（PM话术）**：我会用“命中率/引用覆盖率/拒答正确率/平均延迟/单次成本”做核心指标，并把“数据工程”作为 80% 工作量来规划。 | 是否理解 RAG 的业务价值（可追溯/可更新/降幻觉）；能否讲清端到端链路与关键模块；能否用指标与成本延迟做权衡；是否具备“数据保鲜/运营闭环”意识。 |
| **幻觉治理 & 评测** | 什么是大模型“幻觉”？在企业场景你如何系统性降低幻觉，并证明它真的变好了？ | **一句话**：幻觉=模型在缺乏可靠依据时仍给出“听起来很对但实际不对/无法证实”的内容；治理要靠“证据约束 + 过程控制 + 评测闭环”，而不是只改 prompt。<br><br>**常见成因（面试高频）**：<br>- 训练数据中的统计相关≠事实；模型会“补全空白”。<br>- 企业私域知识缺失/过期；问题超出模型内化知识。<br>- Prompt 注入、上下文噪声、检索召回错误导致“以假为真”。<br><br>**系统性解决方案（从轻到重）**：<br>1) **回答约束**：强制“基于证据回答”，无证据则 **拒答/澄清问题**。<br>2) **RAG + 引用**：输出必须带引用片段与来源；对关键句做证据对齐。<br>3) **结构化输出**：让模型先给结论、再给依据、再给不确定性（PM可定义模板）。<br>4) **多模型/规则校验**：数值、日期、政策条款用规则或工具校验；关键答案走“二次验证”。<br>5) **Human-in-the-loop**：高风险（金融/医疗/法务）加入人工审核与灰度策略。<br><br>**如何证明变好了（评测体系）**：<br>- 建立企业自有 **评测集**：覆盖高频问题、长尾问题、对抗样例（诱导、注入）。<br>- 指标不只看“好不好看”，更看：<br>  - **事实正确率 / 引用正确率（证据是否支持结论）**<br>  - **拒答正确率（该拒是否拒）**<br>  - **一致性（同问多次是否稳定）**<br>  - **业务指标**：工单转人工率、一次解决率、客诉率。<br>- 通过 **A/B + 灰度**：把“质量提升”转成可量化的线上收益/风险下降。<br><br>**PM落地表述**：幻觉治理是“产品风控”，我会按场景分级：可容错（营销文案）强调创意与效率；不可容错（政策/售后承诺）强调证据、拒答、审核与审计。 | 是否能区分“内容不佳”与“事实错误”；是否具备企业级风控思维（拒答/审核/引用/审计）；是否会搭评测集与线上指标闭环；能否把治理方案与成本、延迟、体验做权衡。 |
