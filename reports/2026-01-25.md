## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **大模型原理与幻觉** | 什么是大模型“幻觉” (Hallucination)？作为产品经理，你有哪些落地手段来减少它？ | **原理**：LLM本质是基于概率的“下一个词预测”，它并不掌握事实，只是在模拟语言模式。<br>**PM解法**：<br>1. **RAG (检索增强生成)**：给模型配个“外挂知识库”，强制要求其根据搜索到的参考资料回答，这是目前成本最低、效果最好的手段。<br>2. **反向提示词 (Negative Prompt)**：在系统提示词中明确告知“不知道就说不知道，严禁编造”。<br>3. **工作流校验 (Multi-step Verification)**：通过 Agent 模式，让模型先生成答案，再调用另一个提示词或模型进行“事实核查”。<br>4. **前端引导**：增加信息溯源（引用角标），对高风险内容进行“置信度提示”或人工抽检。 | 考察对 LLM 局限性的认知，以及能否通过 RAG、Prompt 和产品流程设计解决技术缺陷。 |
| **技术协同与交付** | 算法同学反馈某项 AI 功能的准确率只能达到 80%，但业务要求 95% 才能上线，你会怎么办？ | **结论**：不要死磕算法极限，要通过产品设计弥补 15% 的技术鸿沟。<br>**策略**：<br>1. **收窄场景 (Scope Control)**：如果全量场景只有 80%，能否先在 20% 的标准化高频场景实现 95%？通过缩小服务范围确保核心体验。<br>2. **置信度门控 (Thresholding)**：设置置信度阈值。高于 90% 的直接输出，70%-90% 的转为“建议/可选项”，低于 70% 的直接转接人工或报错兜底。<br>3. **人机协同 (Human-in-the-loop)**：将 AI 定位为“助手”而非“替代者”。AI 先处理 80% 的工作并给出初稿，人工进行最后的 20% 审核确认。<br>4. **交互引导**：将选择题改为填空题，或通过 UI 引导用户提供更精准的输入，从而提升模型表现。 | 考察对 ROI 的判断力，以及在算法受限时，如何通过产品经理的“变通能力”实现业务目标。 |
| **Agent 架构趋势** | 为什么说 AI Agent（智能体）是比单纯 Chatbot（聊天机器人）更高级的产品形态？ | **原理**：Chatbot 核心是“对话”，而 Agent 核心是“执行任务”。Agent = LLM + 规划 (Planning) + 记忆 (Memory) + 工具调用 (Tool Use)。<br>**核心差异**：<br>1. **自主性**：Chatbot 是问一句答一句；Agent 接收到一个模糊目标（如“帮我定一张出差门票”）后，能自动拆解步骤并调用 API 执行。<br>2. **闭环能力**：Chatbot 只能输出文本；Agent 能通过插件连接外部世界（如读写文档、订票、操作软件）。<br>3. **反馈迭代**：Agent 具备观察环境反馈并修正计划的能力，能处理更复杂的长链路业务流。<br>**PM挑战**：Agent 的不确定性更高，需要设计完善的“监控告警”和“人工接管”机制。 | 考察对前沿技术趋势（Agentic Workflow）的理解，以及从“内容生成”向“任务达成”转变的产品思维。 |
