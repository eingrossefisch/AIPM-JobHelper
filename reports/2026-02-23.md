### 💡 专家级真题解析（针对上述考点）

#### 1. 百度：如何构建大/小模型的决策框架？（真题解析）
*   **回答思路**：从 **用户场景容错度、成本收益比、响应耗时（P99）** 三个维度构建。
    *   **分流逻辑**：利用“意图识别”模块，将低复杂度的任务（如日常问候、简单事实查询）路由给 **Small Model**，将高复杂度任务（如逻辑推理、长文本总结）路由给 **Large Model**。
    *   **效果兜底**：若小模型输出的置信度低于阈值，则自动触发大模型二次校验（Cascading Models）。
    *   **业务价值**：核心目标是在不显著牺牲用户体验的前提下，追求 **单位Token成本的最优解**。

#### 2. 百度：RAG 场景下如何平衡检索知识与生成能力？（真题解析）
*   **回答思路**：核心在于 **“忠实度控制”**。
    *   **策略**：通过 **Prompt Engineering** 强制模型执行“根据已知信息回答，若无信息则回答不知道”；引入 **引用溯源（Citation）** 机制，要求模型每一句结论必须标注参考文档。
    *   **技术协同**：使用 **Rerank（重排序）** 提高检索精度，确保喂给生成模型的 Top-K 文档高度相关，减少模型受噪声干扰产生的幻觉。

#### 3. 钉钉：AI 效率产品的效果评估体系？（真题解析）
*   **回答思路**：分为 **量化效率指标** 和 **组织价值指标**。
    *   **量化指标**：**AHT（平均处理时长）削减率**、**Task Completion Rate（任务完成率）**、用户对 AI 建议的 **采纳率（Acceptance Rate）**。
    *   **质化/组织指标**：**信息透明度提升**（如未参会人员阅读 AI 摘要后的反馈）、**决策达成速度**。
    *   **护栏指标**：**Bad Case 率**（特别是涉及隐私外泄或逻辑错误的负反馈率）。

#### 4. 钉钉：B/C端 AI 产品设计最大的不同？（真题解析）
*   **回答思路**：
    *   **B端（钉钉）**：强调 **确定性与合规性**。AI 是辅助工具，输出必须符合企业资产安全，追求的是“零差错”或“可追溯”。
    *   **C端（文心/豆包）**：强调 **惊喜感与低门槛**。AI 是伙伴，鼓励发散性输出，允许一定的幻觉来增加趣味性，核心是降低用户的心理负担和操作难度。

| **Tool Use** | 如果实现一个业务功能，给 LLM 绑定 Tool Call (工具调用) 和让 LLM 直接写代码 (Code Interpreter) 运行，PM 该如何选？ | **结论**：预定义高频场景选 **Tool Call**，开放式数据处理/复杂数学选 **Code Interpreter**。<br>**Tool Call**：本质是 PM 和研发定义好的“标准 API”，模型只负责选择工具和提取参数。优点是结果稳定、安全可控、不泄露后端逻辑；缺点是无法处理预定义之外的复杂需求。<br>**Code Interpreter**：模型根据需求动态生成 Python 代码并执行。优点是极度灵活（如处理 Excel、绘图）；缺点是环境隔离成本高（沙箱）、代码可能报错导致任务中断，且存在代码注入的安全风险。 | 考察对“确定性”与“灵活性”的架构权衡，以及安全意识。 |
| **长文本生成** | LLM 存在 Context 限制且容易在生成后期“疲劳”，如何让 AI 胜任 2000 字以上的长文本执行任务？ | **核心策略**：由“单次 Prompt”转向“流程编排 (Workflow)”。<br>**1. 任务拆解**：采用大纲生成 -> 逐段填充 -> 结尾总结的逻辑。不要试图让模型一气呵成，因为 Token 越多，模型注意力越弥散（Middle-out 现象）。<br>**2. 状态保持**：利用 Memory 或临时向量库缓存前文的关键信息（Context），作为后续段落生成的背景约束。<br>**3. 迭代润色**：最后增加一步专门的“一致性检查”Agent，识别段落间的逻辑断层或复读机问题。 | 考察对 LLM 物理边界（注意力机制/Token限制）的理解及工程化解决能力。 |
| **性能与成本** | 在落地 RAG 或 Agent 系统时，有哪些实战经验可以优化成本 (Cost) 和响应延迟 (Latency)？ | **1. 成本优化**：<br>- **模型分级**：路由机制。简单查询走轻量模型（如 GPT-4o-mini / DeepSeek-V3），复杂规划才调用昂贵模型。<br>- **Prompt 缓存**：利用 Embedding 缓存高频相似问题的检索结果，减少 Token 输入。<br>**2. 延迟优化**：<br>- **流式输出 (Streaming)**：优先返回首字（TTFT），通过交互设计缓解用户焦虑。<br>- **并行处理**：在 RAG 链路中，检索知识库与模型初步分析可以并行（多线程）执行，而非串行等待。<br>- **Semantic Cache**：对语义高度相似的问题，直接返回缓存结果，无需请求大模型。 | 考察对 AI 产品商业化落地中“投入产出比”和“用户体验指标”的敏感度。 |
