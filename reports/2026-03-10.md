## 3️⃣ 八股背诵
| 领域 | 问题 (Q) | PM解答 (A) | 考察点 |
| :--- | :--- | :--- | :--- |
| **Multi-Agent** | 相比单智能体，多智能体（Multi-Agent）在落地复杂业务场景时的优势是什么？如何平衡其带来的挑战？ | **结论**：多智能体通过“分工协作”突破了单智能体（Single Agent）在模型容量和专业深度上的极限。<br>**优势**：1. **分工专家化**：将任务拆解为规划、执行、校验等角色，能处理端到端的复杂长流程；2. **并行效率**：多智能体可并行处理子任务（如同时调研5个信源），提升整体吞吐量；3. **容错性**：通过多智能体间的交叉校验、投票机制，显著降低单点的“幻觉”风险。<br>**挑战与权衡**：MAS 会显著增加 Token 成本和响应延迟（Latency）。PM 需要评估任务的“复杂度价值”，仅在单步提示词无法解决且对准确率要求极高的环节引入 MAS。 | 考察对复杂任务流（Workflow）拆解能力及对“系统性成本”的敏感度。 |
| **Tool Calling** | 在 Agent 架构中，让模型进行 Function Call（工具调用）和让模型直接写 Python 代码（Code Interpreter）执行，PM 应该如何选择？ | **结论**：Function Call 胜在“确定性”与“安全性”，Code Interpreter 胜在“灵活性”与“计算上限”。<br>**Function Call**：适用于业务逻辑预定义的场景（如下单、查库存）。优点是输出格式标准（JSON），后端易于处理且权限可控；缺点是无法处理开发者未定义的长尾需求。<br>**Code Interpreter**：适用于复杂数学计算、大规模数据清洗或生成图表。优点是能解决模型自身的计算弱项；缺点是需要隔离的沙箱环境（Sandbox），且代码执行结果具备不确定性。<br>**Trade-off**：企业内部严谨流程选前者，开放式探索工具选后者。 | 考察对 LLM 边界能力的理解，以及在安全性与功能性之间的取舍策略。 |
| **Optimization** | 针对 RAG 或 Agent 系统的高额推理成本和响应延迟，PM 有哪些实用的工程化优化思路？ | **结论**：通过“请求前过滤”和“模型分级”实现成本与体验的帕累托最优。<br>**成本优化**：1. **语义缓存 (Semantic Cache)**：对高频重复提问，直接从缓存向量库取回结果，不触发 LLM 请求；2. **Prompt 裁剪**：在 RAG 环节对检索出的 Context 进行重要度排序，剔除低贡献 Token；3. **模型路由 (Router)**：简单问题路由给小模型（如 GPT-4o-mini），只有复杂逻辑才调用大模型。<br>**延迟优化**：1. **流式输出 (Streaming)**：优化 TTFT（首字响应时间）以缓解用户焦虑；2. **异步执行**：对于长任务 Agent，采用“任务提交-进度查询”的异步交互模式。 | 考察对大模型商业化落地中“算力账单”的掌控力及交互设计经验。 |
